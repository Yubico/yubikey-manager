== Working with the code

=== Repository structure

This repository is a mixed Rust/Python workspace:

[cols="1,2"]
|===
| Path | Description

| `crates/yubikit`
| Core Rust library — protocol implementations for all YubiKey applications

| `crates/yubikit-pyo3`
| PyO3 bindings that expose the Rust library to Python

| `crates/ykman`
| Rust library implementing higher-level ykman operations

| `crates/ykman-cli`
| The `ykman` command-line executable

| `crates/ykman-svc`
| Background service for elevated YubiKey access (Windows)

| `packages/yubikit`
| Python package wrapping the native Rust extension

| `packages/ykman`
| Python wrapper for the `ykman` command-line executable

|===

=== Install dependencies

This project requires Rust 1.88 or later and uses https://rustup.rs/[rustup]
for the Rust toolchain. The
Python parts use https://docs.astral.sh/uv/[uv], which can be skipped when
only developing the Rust parts. Note that changes in the `yubikit` crate often
require modifications to the Python wrapper as well.

==== Linux (Debian-based distributions)

    $ sudo apt install build-essential pkg-config pcscd libpcsclite-dev libudev-dev libdbus-1-dev

==== Linux (RPM-based distributions)

    $ sudo dnf install gcc pkgconf-pkg-config pcsc-lite pcsc-lite-devel systemd-devel dbus-devel

==== macOS

Install the Xcode Command Line Tools:

    $ xcode-select --install

==== Windows

Use the Rust MSVC toolchain with Visual Studio Build Tools, including the
Desktop development with C++ workload and Windows SDK.

=== Setting up the development environment

Clone the repository and set up the Python environment. This builds the
native Rust extension (`_yubikit_native`) and the `ykman` executable, and
installs them into the virtual environment:

    $ git clone https://github.com/Yubico/yubikey-manager.git
    $ cd yubikey-manager
    $ uv sync

After making changes to the Rust code, force a rebuild of the native extension
before testing, since uv otherwise reuses its cached wheel:

    $ uv sync --reinstall-package yubikit

Use `uv run --no-sync` to run commands without uv re-synchronising (and
possibly rebuilding) the environment first, e.g. `uv run --no-sync pytest`.


=== Building the Rust crates and executables

To build the project use cargo build:

    $ cargo build

For a release build:

    $ cargo build --release

=== Building the ykman executable

To build a debug binary:

    $ cargo build -p ykman-cli

The binary is written to `target/debug/ykman`.

For a release build:

    $ cargo build --release -p ykman-cli

The binary is written to `target/release/ykman`.

The `hardware` feature (enabled by default) links against libpcsclite and
hidapi to communicate directly with connected devices. Build without it to
produce a binary that can only communicate via the `ykman-svc` service:

    $ cargo build -p ykman-cli --no-default-features

=== Updating third-party licence notices

The CLI embeds `crates/ykman-cli/licenses.txt`. Normal builds, including
builds from crates.io packages, do not require `cargo-about`.

After changing dependencies, CLI features, the licence policy, or the report
template, regenerate the notices using the same `cargo-about` version as CI:

    $ cargo install cargo-about --version 0.9.1 --locked
    $ cargo fetch --locked
    $ cargo about generate --locked --offline --all-features --fail \
        --manifest-path crates/ykman-cli/Cargo.toml \
        --config crates/ykman-cli/about.toml \
        --output-file crates/ykman-cli/licenses.txt \
        crates/ykman-cli/about-cli.hbs

The report covers the CLI's runtime dependencies across platforms, including
all CLI features, as resolved by `Cargo.lock`. Use `--locked` for release
builds so the dependencies match the bundled notices.
CI checks that the checked-in report matches regeneration and verifies crate
packages without `cargo-about` installed.
Commit the updated report with the dependency or licence-policy changes.

=== Building the Python wrapper

To build the Python wrapper, use `uv`:

    $ uv sync

Because uv caches wheels, any changes to the native layers require you to
force a rebuild of the yubikit package:

    $ uv sync --reinstall-package yubikit

=== Code style & security

https://docs.astral.sh/ruff/[ruff] handles Python style and security linting.
https://mypy-lang.org[mypy], https://github.com/microsoft/pyright[pyright], and
https://github.com/astral-sh/ty[ty] are used for static type checking.
Rust code uses `cargo fmt` and `cargo clippy`, and
https://embarkstudios.github.io/cargo-deny/[cargo deny] checks Rust
dependencies for advisories, licenses, and duplicate versions (see
`deny.toml`).
All checks are wired up via a http://pre-commit.com/[pre-commit] hook:

    $ uv tool install pre-commit
    $ pre-commit install

To run all checks manually:

    $ pre-commit run --all

=== CI build and signing inputs

Rust setup uses `actions-rust-lang/setup-rust-toolchain`, pinned to a reviewed
release commit SHA. The explicit `toolchain: stable` input selects the current
stable compiler. Rust caching is enabled for host builds: push runs can save
caches, while pull requests can restore caches but cannot save them. Linux wheel
builds inside Maturin containers are not covered by this host cache.

The setup action's additional warning policy and `RUSTFLAGS` overrides are
disabled, preserving the existing Clippy policy and target-specific linker
flags in `.cargo/config.toml`. Rust build jobs explicitly retain Cargo's default
dev-profile debug level of 2 rather than the action's default of 0.

CI Cargo builds, tests, Clippy checks and Maturin wheel builds use `--locked`.
The source-package job also passes `--locked` to Maturin's PEP 517 native
builds, uses locked uv project commands, and checks that source packaging did
not modify either lockfile. Dependency changes must include updated lockfiles.

The non-hardware Rust unit-test step overrides the serial test default with
`--test-threads="$(nproc)"` to use the runner's available CPUs. The serial
default in `.cargo/config.toml` remains in place for device tests.

Windows signing uses a digest-pinned Scribe container. When updating it, review
the image release and resolve its registry digest, then update all four signing
jobs for the x64 and ARM64 executables and installers.

Signing containers receive only `GOOGLE_APPLICATION_CREDENTIALS`, `CI`,
`GITHUB_EVENT_NAME`, `GITHUB_REF`, and `GITHUB_REPOSITORY` from the runner.
Scribe needs the CI metadata to construct the release reference; keep these
named inputs rather than forwarding the full runner environment.

=== Dependency updates

Dependabot checks GitHub Actions, the Cargo and uv workspaces, and remote
pre-commit hook revisions monthly. Cargo, uv and pre-commit each group patch
updates and allow up to five open version-update PRs; minor and major updates
remain separate. Rust `0.x` minor updates can contain breaking changes.
The existing GitHub Actions group includes all update types.

Review dependency changes and CI results before merging; auto-merge is not
enabled by this configuration. Keep manifest and lockfile changes together.
Local pre-commit hooks and tool versions embedded in CI commands are not
covered by these update entries.

=== Unit tests

These tests do not require a YubiKey to be connected.

Rust unit tests:

    $ cargo test --lib

Python unit tests:

    $ uv run pytest

=== Rust device tests

WARNING: ONLY run these on dedicated developer keys, as it will permanently
delete data on the device!

The test suite automatically detects whether the device is connected over USB or NFC.
Tests that require a physical USB connection (e.g., OTP/FIDO HID) are automatically
skipped when the device is connected over NFC.

    $ YUBIKEY_SERIAL=123456 cargo test -p yubikit --test device_tests -- --test-threads=1 --no-capture

For devices without a serial number, use `YUBIKEY_SERIAL=-1`:

    $ YUBIKEY_SERIAL=-1 cargo test -p yubikit --test device_tests -- --test-threads=1  --no-capture

The same command works whether the device is connected via USB or via an NFC reader.

You can target specific tests by specifying the test name after the command,
eg. append "fido" to only run the FIDO tests.

NOTE: --test-threads 1 is required as the device tests interact with a connected
YubiKey and cannot be run in parallel. --no-capture displays output showing which
tests were skipped, and why.

=== CLI device tests

WARNING: ONLY run these on dedicated developer keys, as it will permanently
delete data on the device!

The `ykman-cli` crate has its own device tests, which run the `ykman`
executable against a connected YubiKey. They use the same `YUBIKEY_SERIAL`
environment variable as the Rust device tests:

    $ YUBIKEY_SERIAL=123456 cargo test -p ykman-cli --test cli_tests -- --test-threads=1

As with the Rust device tests, append a test name filter (e.g. "piv") to only
run a subset.

FIDO command tests require the FIDO2 application, not just the USB FIDO
interface, which can also be present on U2F-only devices.

=== Python device tests

WARNING: ONLY run these on dedicated developer keys, as it will permanently
delete data on the device!

Specify the serial number of the YubiKey to test with (shown by `ykman list`):

    $ uv run pytest --device 123456

For devices without a serial number, use `--no-serial` instead of `--device`.

This works for both USB and NFC-connected devices. The test suite automatically
skips tests that are not applicable to the attached device.

=== Generating documentation

==== Rust (cargo doc)

Generate and open API documentation for the `yubikit` crate:

    $ cargo doc -p yubikit --open

To include documentation for all workspace crates:

    $ cargo doc --workspace --open

The generated HTML is written to `target/doc/`.

==== Python (Sphinx)

Generate HTML API documentation for the Python packages:

    $ uv run sphinx-build docs docs/_build/html

Open `docs/_build/html/index.html` in a browser to view the result.

=== Release checklist

A release includes both the Rust crates on crates.io and the Python packages on
PyPI. Python package versions use PEP 440 spelling: the initial alpha is
`yubikit` `1.0.0a0` and `yubikey-manager` `6.0.0a0`, corresponding to Rust
`1.0.0-alpha.0` and `6.0.0-alpha.0`. Keep the Python package metadata, the
manager's minimum `yubikit` dependency, and both workspace lockfiles consistent
with the release.

. Verify the declared Rust minimum, all workspace targets and features, unit
  tests, and relevant device tests. Require green Linux, macOS and Windows CI
  for the final release commit.
. Verify Rust API documentation, including docs.rs native-dependency handling,
  and build the Python Sphinx documentation.
. Build and verify all publishable Rust crate packages. Build both Python
  source distributions and the wheel matrix for supported platforms,
  architectures and Python versions. Test source builds from the source
  distributions and clean wheel installations outside the workspace; check
  installed metadata, Python imports and the `ykman` executable version.
. Confirm publishing access and intended ownership for all four crates.io
  projects and both PyPI projects, and configure publishing credentials or
  trusted publishing.
. Prepare release notes and tag the exact source commit used for the verified
  artifacts.
. Publish Rust crates in dependency order: `yubikit`, then `ykman`, then
  `ykman-cli` and `ykman-svc`. Keep the `yubikit-pyo3` crate unpublished on
  crates.io; its native extension is distributed inside the Python `yubikit`
  wheels and source distribution.
. Publish the verified Python wheels and source distributions to PyPI:
  `yubikit` first, then `yubikey-manager`.
. Smoke-test registry-only Rust installation and clean Python installation
  from PyPI, explicitly selecting the prerelease versions for an alpha.
